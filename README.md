# 메뉴를 찾지 않는 은행 앱 (프로토타입)

> ### ⚠️ 비공식 개인 프로토타입입니다
> **iM뱅크·DGB금융그룹과 아무 관계가 없습니다.** 어떤 승인·제휴·의뢰도 받지 않았습니다.
> 화면의 계좌번호·거래내역·수취인·잔액은 **전부 제가 만든 가상 데이터**이며,
> 실제 금융 거래는 일어나지 않습니다. 실제 은행 서비스로 사용할 수 없습니다.
> 아이디어 구현을 보여주기 위한 개인 습작입니다.

은행 앱에는 기능이 다 있는데, **어디 있는지 못 찾습니다.** 종부세 납부 서류, 카드 명세서
엑셀 추출, 자동이체 해지 — 메뉴를 다섯 단계씩 들어가야 합니다.

그래서 메뉴 대신 **말로 찾는** 쪽을 만들어 봤습니다.
`돈이 자꾸 빠져나가는데 뭔지 모르겠어` 같은 막연한 문장에도, 모델이 **어떤 기능을 쓸지
스스로 판단**해 거래내역을 조회하고 정리해 줍니다.

---

## 무엇을 보여주려 했나

**1. 명령이 아니라 상태를 말해도 된다**
"카드 명세서 조회" 대신 "돈이 자꾸 빠져나가는데" 로 시작할 수 있어야 합니다.
의도가 불분명할 때 모델이 먼저 조회하고, 그다음 선택지를 칩으로 제시합니다.

**2. AI가 무엇을 하는지 보인다**
오른쪽 패널에 **호출한 도구 이름을 그대로 노출**합니다(`get_transactions`, `find_documents` …).
금융 앱에서 "알아서 해줬다"는 불투명함은 그 자체로 위험이라고 봤습니다.

**3. 묻혀 있던 기능을 꺼낸다**
카드 명세서 엑셀 추출, 세금 자동납부 등록, 이체한도 변경 —
메뉴 깊이에 갇혀 있던 기능을 **도구 29개**로 평평하게 펼쳤습니다.

## 구성

```
index.html          모바일 프레임 + AI 로그 패널 2단 레이아웃
js/agent.js         시스템 프롬프트 · 대화 루프 · 도구 호출 오케스트레이션
js/tools.js         도구 정의 29종 (조회 / 서류 / 이체 / 카드 / 대출 / 자동이체 / 정보변경)
js/knowledge.js     업무 절차 지식 DB — 메뉴 경로 기반 RAG 흉내
js/data.js          가상 고객·계좌·카드·거래 데이터
js/ui.js demo.js    렌더링 · 시나리오 진행
api/chat.js         서버리스 중계 — 키를 브라우저에 노출하지 않기 위한 얇은 프록시
시연영상_각본.md     2분 시연 시나리오 6개
```

**도구 29종**: `list_cards` `get_card_autopays` `cancel_card` `move_autopays`
`find_documents` `issue_documents` `list_accounts` `lookup_payee` `prepare_transfer`
`get_transfer_limit` `change_transfer_limit` `search_knowledge` `get_account_balance`
`get_transactions` `get_loans` `export_card_statement` `update_personal_info`
`report_card_lost` `setup_tax_autopay` `register_autopay` `cancel_autopay`
`prepare_loan_repay` `extend_loan` 외

## 설계에서 신경 쓴 것

| | |
|---|---|
| **키를 브라우저에 두지 않는다** | `api/chat.js` 서버리스 함수가 중계합니다. 프런트엔드는 키를 모릅니다 |
| **모델·토큰을 서버에서 고정** | 클라이언트가 모델이나 토큰 상한을 바꿀 수 없습니다. 비용 백스톱입니다 |
| **중계 범위 한정** | `chat/completions` 한 경로만 통과시킵니다 |
| **실행 전 확인 단계** | 이체·해지처럼 되돌리기 어려운 동작은 `prepare_*`로 안을 만들어 보여준 뒤 사용자 확인을 받습니다 |

## 실행

```bash
cp config.example.js config.js     # 설정값 입력
# OpenAI 키는 서버 환경변수로 (코드·클라이언트에 넣지 않습니다)
npx vercel dev
```

## 한계 — 적어 둡니다

- **백엔드가 없습니다.** 모든 데이터는 클라이언트의 가상 객체이고, 아무것도 저장되지 않습니다.
- 지식 DB는 벡터 검색이 아니라 **키워드 매칭**입니다. RAG의 흉내지 RAG가 아닙니다.
- 실제 은행 연동·인증·감사로그·거래 무결성은 **전혀 다루지 않았습니다.** 프로토타입의 범위 밖입니다.
- 응답에 2~4초 걸립니다.
